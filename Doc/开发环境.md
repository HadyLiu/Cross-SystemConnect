# 开发环境搭建

> Cross-SystemConnect（CSC）· Rust · **不使用 MSVC**  
> Windows 和 Linux 的可执行文件都由 Docker 一次生成，不在 Windows 或 Linux 上分别安装工具链编译。  
> 版本号在根目录 `Cargo.toml` 的 `[workspace.package] version`（当前 `0.1.0`）。

更完整的产品与架构说明见 [设计方案.md](设计方案.md)。

---

## 1. 用 Docker 生成 Windows 和 Linux 程序

不在 Windows 上安装 MSYS2，也不在 Linux 上用本机 `cargo build` 出发布程序。镜像 `cross-systemconnect-packager` 里先编 Linux，再用 MinGW 交叉编译 Windows，一次得到两端的界面和内核。

### 1.1 准备 Docker

当前用户要能访问 Docker。若 `docker images` 提示 permission denied，把用户加入 `docker` 组后重新登录：

```bash
sudo usermod -aG docker "$USER"
```

重新登录后确认：

```bash
id
docker images
```

`id` 的组列表里应有 `docker`。

### 1.2 构建

在仓库根目录执行：

```bash
bash scripts/package-docker.sh
```

镜像 `cross-systemconnect-packager:latest` 只包含编译工具。镜像已经存在时，脚本不再构建镜像，只把源码挂进容器编译，产物写到 `dist/`。本机还没有这个镜像时才会构建。要主动重建镜像：

```bash
bash scripts/package-docker.sh --image
```

镜像定义在 `packaging/Dockerfile`，容器内编译脚本是 `packaging/compile.sh`。

| 系统 | 可执行文件 | 压缩包 |
|------|------------|--------|
| Linux | `dist/linux/Cross-SystemConnect`、`dist/linux/Cross-SystemConnect-core` | `dist/Cross-SystemConnect-linux-x86_64.tar.gz` |
| Windows | `dist/windows/Cross-SystemConnect.exe`、`dist/windows/Cross-SystemConnect-core.exe` | `dist/Cross-SystemConnect-windows-x86_64.zip` |

界面启动时拉起同目录下的内核。`dist/` 与镜像内的编译目录都不要提交到 Git。

Windows 仍使用 GNU 目标（`x86_64-pc-windows-gnu`），不使用 MSVC。交叉编译只发生在镜像里。

### 1.3 运行时依赖

这些库不用来编译，装在实际运行程序的电脑上。

Windows 设置界面依赖 Edge WebView2。一般 Windows 10/11 已自带；若缺失请安装：  
[WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)

Linux 在 X11 上注入键鼠时，运行时打开 `libX11.so.6` 和 `libXtst.so.6`：

```bash
sudo apt install libx11-6 libxtst6
```

Wayland 上不走 XTest，也不弹出「远程桌面 / 允许远程交互」。被控端通过 `/dev/uinput` 注入指针和键盘。程序以 root 启动时会写入 `/etc/udev/rules.d/71-cross-systemconnect.rules`。用普通用户运行前执行一次：

```bash
sudo tee /etc/udev/rules.d/71-cross-systemconnect.rules >/dev/null << 'EOF'
KERNEL=="uinput", MODE="0666", OPTIONS+="static_node=uinput"
SUBSYSTEM=="input", KERNEL=="event*", ATTRS{name}=="Cross-SystemConnect", \
  ENV{ID_INPUT}="1", ENV{ID_INPUT_MOUSE}="1", ENV{ID_INPUT_KEYBOARD}="1", \
  ENV{LIBINPUT_ATTR_ACCEL_PROFILE}="flat", ENV{LIBINPUT_ATTR_ACCEL_SPEED}="0"
EOF
sudo udevadm control --reload-rules
sudo udevadm trigger --sysname-match=uinput --action=change
```

日志里应出现 `Wayland pointer control uses /dev/uinput`。

## 3. 运行与调试

### 3.1 日常运行

每次改完代码，按下面三步走：

1. 托盘右键「退出」（界面和内核一起退出）。
2. 用 Docker 重新生成两端程序：
   ```bash
   bash scripts/package-docker.sh
   ```
3. 运行刚导出的界面，它会拉起同目录下的内核：
   ```bash
   # Linux
   ./dist/linux/Cross-SystemConnect
   # Windows
   .\dist\windows\Cross-SystemConnect.exe
   # 启动并立即打开设置
   ./dist/linux/Cross-SystemConnect --open-settings
   ```

注意：

- **一定先「退出」再运行。** 界面启动时只要已经有内核在应答，就直接连上它，不会启动新的内核，新功能看起来就像没生效。退出后可以用 `pgrep -a Cross-SystemConnect`（Windows 看任务管理器）确认没有残留。界面被强制结束（`kill -9`、任务管理器只结束界面）时内核会留下，需要手动结束。
- **用普通用户运行，不要用 root。** 以 root 运行时配置和证书在 `/root/.config/cross-systemconnect/`，和普通用户的不是同一份。
- 日志默认写到程序目录下的 `log.txt`，即 `dist/linux/log.txt` 或程序所在目录；设置里的日志页显示实际写入的文件。

### 3.2 关掉之前运行的程序

正常情况下托盘右键「退出」就够了：界面先让内核退出，1.5 s 后内核还在就按 PID 强制结束，然后界面自己退出。

托盘图标不见了、界面卡住，或者不确定有没有旧程序在跑时，按下面的方法处理。

**Linux**

```bash
# 1. 查看还在运行的（界面是 Cross-SystemConnect，内核是 Cross-SystemConnect-core）
pgrep -a Cross-SystemConnect
ps -o pid,user,lstart,args -C Cross-SystemConnect,Cross-SystemConnect-core   # 连同启动用户和时间

# 2. 正常结束（内核收到 TERM 会退出）
pkill -f Cross-SystemConnect

# 3. 几秒后还在，强制结束
pkill -9 -f Cross-SystemConnect

# 以 root 启动的（USER 一列是 root），普通用户结束不了，要加 sudo
sudo pkill -f Cross-SystemConnect

# 4. 再查一次，没有输出就说明都关了
pgrep -a Cross-SystemConnect
```

- `-f` 按完整命令行匹配，界面和内核会一起结束，不管是 debug 还是 release 目录里的。
- 内核残留时，它的父进程通常是 `systemd --user` 或 `1`，说明界面已经被强制结束，内核变成了孤儿进程；这不是开机自启服务，直接结束即可。
- 本机 IPC 套接字（`$XDG_RUNTIME_DIR/cross-systemconnect-core.sock`）不用手动删除：下一个内核启动时发现连不上，会自己删掉重建。

**Windows**

- 任务管理器 →「详细信息」，结束 `Cross-SystemConnect.exe` 和 `Cross-SystemConnect-core.exe`，两个都要结束。
- 或者在命令行里：

```bat
tasklist | findstr Cross-SystemConnect
taskkill /F /IM Cross-SystemConnect.exe
taskkill /F /IM Cross-SystemConnect-core.exe
```

**开机自启**

自启项记录的是打开「开机自启」时正在运行的那个程序的路径（Linux 写在 `~/.config/autostart/cross-systemconnect.desktop`，Windows 写在注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）。要改成 Docker 导出的程序时，用 `dist/` 里的界面运行后，在设置里重新打开一次开机自启，让它记下新路径。

### 3.3 调试

发布程序只从 Docker 来。改完代码后重新执行 `bash scripts/package-docker.sh`，再运行 `dist/linux/Cross-SystemConnect` 或 `dist\windows\Cross-SystemConnect.exe`。只看内核日志时，直接运行同目录的 `Cross-SystemConnect-core`。

| 项目 | Windows | Linux |
|------|---------|-------|
| 配置 | `%APPDATA%\Cross-SystemConnect\config.json`（兼容迁移旧 `CSC`） | `~/.config/cross-systemconnect/config.json` |
| 内核日志 | 程序目录 `log.txt`；程序目录不能写时 `%APPDATA%\Cross-SystemConnect\Cross-SystemConnect.log` | 程序目录 `log.txt`；程序目录不能写时 `~/.local/state/cross-systemconnect/Cross-SystemConnect.log` |
| 界面日志 | `%APPDATA%\Cross-SystemConnect\ui.log` | `~/.config/Cross-SystemConnect/ui.log` |
| 本机 IPC | Named Pipe `\\.\pipe\Cross-SystemConnect-core` | `$XDG_RUNTIME_DIR/cross-systemconnect-core.sock` |
| 本机证书 | `%APPDATA%\Cross-SystemConnect\identity.crt` 与 `identity.key` | `~/.config/cross-systemconnect/identity.crt` 与 `identity.key` |

发布程序在 `dist/linux/` 与 `dist/windows/`。界面启动时拉起旁边的内核；内核已在运行时，后启动的内核退出并连到现有进程。

Windows 托盘双击打开设置。Linux 托盘左键打开设置，右键是菜单。

日志级别在设置的日志页修改（默认 info），保存后立即生效，不读 `RUST_LOG`。两个日志文件都不超过 100 KB，满了清空重写。

## 4. 工程结构（开发时常用）

```text
Cross-SystemConnect/
├── Cargo.toml              # workspace
├── .cargo/config.toml      # 镜像内交叉编译 Windows 时的链接器覆盖仍可读它
├── packaging/              # Dockerfile 与导出脚本
├── crates/
│   ├── csc-proto/          # 跨机协议 + IPC 类型
│   ├── csc-config/         # 配置
│   ├── csc-platform/       # 平台抽象
│   ├── csc-core/           # 内核二进制
│   └── csc-ui/             # 托盘 + WebView
├── scripts/                # package-docker.sh：生成 Windows 与 Linux 程序
├── Doc/                    # 设计与开发文档
└── resources/              # 图标等资源
```

## 5. 版本号

只改根目录 `Cargo.toml`：

```toml
[workspace.package]
version = "0.1.0"
```

各 crate 使用 `version.workspace = true`，不要再单独写版本。界面程序编译时读入这个版本：设置窗口左上角软件名下方显示 `v0.1.0`，窗口标题和托盘提示为 `Cross-SystemConnect v0.1.0`。改版本后需要重新执行 `bash scripts/package-docker.sh` 才会变。

发布标签与这里保持一致：`0.1.0` 对应 `v0.1.0`。

## 6. 发布

不使用 GitHub Actions，也不在 Windows 和 Linux 上各编一次。两端程序都由同一次 Docker 构建生成，用**同一个版本号**上传到同一个 Release。

```bash
bash scripts/package-docker.sh
```

产物见第 1.2 节。上传前安装并登录 GitHub CLI（只需一次）：

```bash
# https://cli.github.com/
gh auth login
```

版本号与 `Cargo.toml` 一致。Release 不存在时新建，已存在时追加或覆盖同名文件：

```bash
gh release create v0.1.0 --title v0.1.0 --notes "Built with Docker." \
  dist/Cross-SystemConnect-linux-x86_64.tar.gz \
  dist/Cross-SystemConnect-windows-x86_64.zip
```

已有该版本时改为：

```bash
gh release upload v0.1.0 --clobber \
  dist/Cross-SystemConnect-linux-x86_64.tar.gz \
  dist/Cross-SystemConnect-windows-x86_64.zip
```

## 7. 常见问题

**Q: 第一次 Docker 构建很慢？**  
A: 正常。第一次要拉取 Rust 基础镜像并装好 MinGW 等工具，随后还要编译 Linux 与 Windows 两套依赖。镜像已经存在时，再执行 `bash scripts/package-docker.sh` 不会重建镜像，只增量编译。只有加上 `--image` 才会重建镜像。

**Q: `docker images` 提示 permission denied？**  
A: 当前用户不在 `docker` 组。执行 `sudo usermod -aG docker "$USER"` 后重新登录，再用 `id` 确认组里有 `docker`。

**Q: 构建在拉取 `rust:1-bookworm` 时超时？**  
A: 再执行一次 `bash scripts/package-docker.sh --image`。Docker 守护进程偶尔会走不通的 IPv6 地址，重试通常会改走 IPv4。镜像已经存在时，普通的 `bash scripts/package-docker.sh` 不会再拉取基础镜像。

**Q: 设置窗空白 / WebView 打不开**  
A: Windows 上安装或修复 WebView2 Runtime。Linux 上需要图形会话，不要在无界面的服务器里开设置窗。

**Q: Linux 已经连上，但对端指针不动，或弹出「远程桌面 / 允许远程交互」后无响应？**  
A: Wayland 被控端必须用 `/dev/uinput`，不能走 XTest。按第 1.3 节写入 udev 规则后再运行 `dist/linux/` 里的程序。日志里应有 `Wayland pointer control uses /dev/uinput`。X11 会话则安装 `libx11-6` 和 `libxtst6`。程序本身用 Docker 重新生成，不要在本机 `cargo build`。

**Q: Windows 报「端口只允许使用一次」（os error 10048），或第二个内核马上退出？**  
A: 已经有一个内核占用命名管道 `\\.\pipe\Cross-SystemConnect-core` 和控制端口 24900。后启动的内核发现管道已被占用后会退出，避免再抢端口。到任务管理器结束旧的 `Cross-SystemConnect` 和 `Cross-SystemConnect-core`，只保留一个 `dist\windows\Cross-SystemConnect.exe`。

**Q: 改了代码、重新生成后，功能没变化（快捷键还是旧的、没有 `log.txt` 等）？**  
A: 运行的还是旧内核。先托盘「退出」，再 `bash scripts/package-docker.sh`，然后运行 `dist/linux/Cross-SystemConnect` 或 `dist\windows\Cross-SystemConnect.exe`。界面若连上还在运行的旧内核，新程序不会被用到。

**Q: 两台电脑搜不到、连不上？**  
A: 两边选择同一块网卡所在的 /24。搜索只扫描当前选中地址的网段，默认控制端口是 24900。控制通道是 TLS，旧的明文程序连不上，两边都要换成带加密的版本。日志里的 `tls handshake` 失败就是这一类。

**Q: 信任过一次，后来又弹出信任，或主机拒绝连接？**  
A: 对方的 `identity.key` 换过，证书指纹变了。被控端会再问一次；键鼠主机发现指纹不同会直接拒绝。确认是这台电脑后重新信任。不要把 `identity.key` 拷到另一台机器。

**Q: 能否提交 `dist/` 或 Docker 构建缓存？**  
A: 不能。`dist/` 已由 `.gitignore` 排除，只提交源码与文档。发布文件放在 GitHub Release 上。
