# 开发环境搭建

> Cross-SystemConnect（CSC）· Rust · **不使用 MSVC**  
> Windows 使用 **MSYS2 UCRT64 + x86_64-pc-windows-gnu**；Linux 使用系统 `rustc` / `cargo`。  
> 版本号在根目录 `Cargo.toml` 的 `[workspace.package] version`（当前 `0.1.0`）。

更完整的产品与架构说明见 [设计方案.md](设计方案.md)。

---

## 1. Windows（推荐：MSYS2 UCRT64）

### 1.1 安装 MSYS2

1. 从 [https://www.msys2.org/](https://www.msys2.org/) 安装 MSYS2。
2. 打开 **UCRT64** 终端（不要用 MSYS / MINGW32）。
3. 更新并安装工具链：

```bash
pacman -Syu
pacman -S --needed mingw-w64-ucrt-x86_64-toolchain mingw-w64-ucrt-x86_64-pkgconf
```

4. 将 UCRT64 的 `bin` 加入系统或用户 **PATH**，例如：

```text
C:\msys64\ucrt64\bin
```

（若安装路径不同，改为你的实际路径。）确认：

```bash
gcc --version
```

### 1.2 安装 Rust（GNU 工具链）

```bash
# 安装 rustup 后：
rustup toolchain install stable-x86_64-pc-windows-gnu
rustup default stable-x86_64-pc-windows-gnu
```

在本仓库目录里执行 `rustup show`，`active toolchain` 应为 `stable-x86_64-pc-windows-gnu`。

`.cargo/config.toml` 只在编译 Windows GNU 目标时指定 `gcc` / `ar`，**不会**把 Linux 改成交叉编译 Windows。

**不要**使用 `x86_64-pc-windows-msvc` / Visual Studio `link.exe`。

### 1.3 WebView2 Runtime

设置界面依赖 Edge WebView2。一般 Windows 10/11 已自带；若缺失请安装：  
[WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)

### 1.4 克隆与构建

```bash
git clone https://github.com/HadyLiu/Cross-SystemConnect.git
cd Cross-SystemConnect

# PATH 需能找到 gcc
cargo build --release -p csc-core -p csc-ui
cargo test
```

产物路径示例：

```text
target/release/Cross-SystemConnect-core.exe
target/release/Cross-SystemConnect.exe
```

`target/` 为生成目录，**不要提交到 Git**（已在 `.gitignore` 中忽略）。

## 2. Linux

### 2.1 依赖（Debian / Ubuntu 示例）

编译界面和链接系统库：

```bash
sudo apt update
sudo apt install build-essential pkg-config \
  libwebkit2gtk-4.1-dev \
  libx11-dev libxi-dev libxtst-dev libxfixes-dev libxrandr-dev \
  libxdo-dev \
  libayatana-appindicator3-dev
```

（具体 WebKitGTK 包名以 wry / 发行版文档为准。）

键鼠注入在运行时打开 `libX11.so.6` 和 `libXtst.so.6`，不在编译时链接。缺这两个库时 `cargo build` 仍然成功，但被控端指针不会动，日志里会出现 `cannot load libXtst.so.6`。在实际运行程序的 Linux 上安装：

```bash
sudo apt install libx11-6 libxtst6
```

`libx11-dev`、`libxtst-dev` 一般会带上这两个运行库。只把编好的程序拷到另一台机器时，那台机器仍要单独安装 `libx11-6` 和 `libxtst6`。

会话必须是 X11，或带 XWayland 且 `DISPLAY` 有效的 Wayland。没有 XWayland 的纯 Wayland 不能移动指针，日志为 `XOpenDisplay failed`。

### 2.2 Rust

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
rustc --version
```

不要在 Linux 上安装或写死 `stable-x86_64-pc-windows-gnu`。仓库不再用 `rust-toolchain.toml` 指定 Windows 工具链；进入目录后 `rustc --version` 应显示本机 Linux 目标。

### 2.3 构建

```bash
cargo build --release -p csc-core -p csc-ui
cargo test
```

改过 Linux 注入或协议后，先把同一份源码同步到 Linux 再编译。键鼠注入依赖上一节的 `libx11-6`、`libxtst6`，以及 X11 或 XWayland。

## 3. 运行与调试

```bash
# 仅内核（无 UI）
cargo run -p csc-core

# 托盘 UI（自动拉起内核；默认不弹窗）
cargo run -p csc-ui
# 启动并立即打开设置
cargo run -p csc-ui -- --open-settings
```

| 项目 | Windows | Linux |
|------|---------|-------|
| 配置 | `%APPDATA%\Cross-SystemConnect\config.json`（兼容迁移旧 `CSC`） | `~/.config/cross-systemconnect/config.json` |
| 内核日志 | `%APPDATA%\Cross-SystemConnect\Cross-SystemConnect.log` | `~/.local/state/cross-systemconnect/Cross-SystemConnect.log` |
| 界面日志 | `%APPDATA%\Cross-SystemConnect\ui.log` | `~/.config/Cross-SystemConnect/ui.log` |
| 本机 IPC | Named Pipe `\\.\pipe\Cross-SystemConnect-core` | `$XDG_RUNTIME_DIR/cross-systemconnect-core.sock` |
| 本机证书 | `%APPDATA%\Cross-SystemConnect\identity.crt` 与 `identity.key` | `~/.config/cross-systemconnect/identity.crt` 与 `identity.key` |

发布构建的程序在 `target/release/`（Windows 为 `Cross-SystemConnect.exe` 与 `Cross-SystemConnect-core.exe`）。界面启动时拉起旁边的内核；内核已在运行时，后启动的内核退出并连到现有进程。

Windows 托盘双击打开设置。Linux 托盘左键打开设置，右键是菜单。

常用环境变量：

```bash
# 提高日志级别（若代码侧支持 RUST_LOG / tracing filter）
set RUST_LOG=info
# Linux:
export RUST_LOG=info
```

```text
│   ├── csc-core/           # 内核二进制

```

## 5. 版本号

只改根目录 `Cargo.toml`：

```toml
[workspace.package]
version = "0.1.0"
```

各 crate 使用 `version.workspace = true`，不要再单独写版本。界面程序编译时读入这个版本：设置窗口左上角软件名下方显示 `v0.1.0`，窗口标题和托盘提示为 `Cross-SystemConnect v0.1.0`。改版本后需要重新编译 `csc-ui` 才会变。

发布标签与这里保持一致：`0.1.0` 对应 `v0.1.0`。

## 6. 本地 CI / CD

不使用 GitHub Actions。在本机检查、打包，再把程序上传到 GitHub Release。Windows 和 Linux 各编一次，用**同一个版本号**传到同一个 Release。文件名按系统分开，后上传的不会盖掉先上传的。

先装一次安全检查和上传工具（两台机器都要）：

```bash
cargo install cargo-audit --locked
# https://cli.github.com/ 安装 gh 后：
gh auth login
```

Windows 不要直接运行 `scripts\local-ci.ps1`，系统执行策略会拦截。用下面的启动器，它会绕过该限制，不用改系统策略。

只检查并打包，不上传：

```bash
# Windows
scripts\local-ci.cmd

# Linux
bash scripts/local-ci.sh
```

检查顺序是：格式化、单元测试、Clippy（正确性和可疑写法）、`cargo audit`、release 构建、打包。结束时打印一张表，每一项是 `pass`、`fail` 或 `skip`。全部是 `pass` 时，最后一行 `overall` 为 `pass`；前面有失败时后面的项为 `skip`，`overall` 为 `fail`。通过后程序在 `dist/`：

| 系统 | 文件 |
|------|------|
| Windows | `dist/Cross-SystemConnect-windows-x86_64.exe`、`dist/Cross-SystemConnect-core-windows-x86_64.exe` |
| Linux | `dist/Cross-SystemConnect-linux-x86_64`、`dist/Cross-SystemConnect-core-linux-x86_64` |

上传时版本号与 `Cargo.toml` 一致。先在一台机器上执行，Release 不存在时会新建；另一台用同一个版本号再执行一次，只追加本系统的两个文件。先后顺序可以换。

```bash
# Windows
scripts\local-ci.cmd -Upload -Version v0.1.0

# Linux（先把代码同步到同一提交）
bash scripts/local-ci.sh --upload v0.1.0
```

发完后这个 Release 里共四个文件：界面程序和内核各一份，Windows、Linux 各一套。标签指向当前提交。工作区若还有未提交改动，上传的是这次本地编出来的程序。

## 7. 常见问题

**Q: 第一次 `cargo build --release` 很慢？**  
A: 正常。`windows` / `wry` / `webview2-com` 等依赖首次编译耗时长。日常请用：

```bash
cargo build -p csc-core -p csc-ui          # dev，增量快
cargo build --release -p csc-core -p csc-ui # 仅发布时
```

仓库已关闭 release LTO、限制 tokio 特性，以缩短链接与编译时间。

**Q: `error: target tuple in channel name 'stable-x86_64-pc-windows-gnu'`**  
A: 当前目录把工具链写成了 Windows 目标，Linux 上的 rustup 会直接拒绝，`rustc --version` 也会失败。更新到去掉 `rust-toolchain.toml` 的版本后，重新开一个终端再执行 `source "$HOME/.cargo/env"` 和 `rustc --version`。

**Q: `linker 'link.exe' not found`**  
A: 当前在用 MSVC 工具链。执行 `rustup default stable-x86_64-pc-windows-gnu`，并确认在本仓库目录下 `rustc -vV` 的 `host` 为 `x86_64-pc-windows-gnu`。

**Q: `gcc.exe` / linker not found**  
A: 把 MSYS2 `ucrt64\bin` 加入 PATH，新开终端后再 `cargo build`。

**Q: 设置窗空白 / WebView 打不开**  
A: 安装或修复 WebView2 Runtime；确认以 GUI 方式运行 `csc-ui`（非纯无头服务器环境）。

**Q: Linux 已经连上，但对端指针不动？**  
A: 在被控端安装 `libx11-6` 和 `libxtst6`，并在 X11 或 XWayland 下重新运行。日志里的 `cannot load libXtst.so.6` 表示缺运行库；`XOpenDisplay failed` 表示没有可用的 `DISPLAY`。同步源码后执行 `cargo build --release -p csc-core -p csc-ui`。

**Q: Windows 报「端口只允许使用一次」（os error 10048），或第二个内核马上退出？**  
A: 已经有一个内核占用命名管道 `\\.\pipe\Cross-SystemConnect-core` 和控制端口 24900。后启动的内核发现管道已被占用后会退出，避免再抢端口。到任务管理器结束旧的 `Cross-SystemConnect` 和 `Cross-SystemConnect-core`，只保留一个 `target\release\Cross-SystemConnect.exe`。

**Q: 两台电脑搜不到、连不上？**  
A: 两边选择同一块网卡所在的 /24。搜索只扫描当前选中地址的网段，默认控制端口是 24900。控制通道是 TLS，旧的明文程序连不上，两边都要换成带加密的版本。日志里的 `tls handshake` 失败就是这一类。

**Q: 信任过一次，后来又弹出信任，或主机拒绝连接？**  
A: 对方的 `identity.key` 换过，证书指纹变了。被控端会再问一次；键鼠主机发现指纹不同会直接拒绝。确认是这台电脑后重新信任。不要把 `identity.key` 拷到另一台机器。

**Q: 运行 `scripts\local-ci.ps1` 提示「禁止运行脚本」？**  
A: 改用 `scripts\local-ci.cmd`。不要为了这条脚本去改系统的执行策略。

**Q: 能否提交 `target/` 或 `dist/`？**  
A: 不能。生成物已由 `.gitignore` 排除，只提交源码与文档。发布文件放在 GitHub Release 上。
