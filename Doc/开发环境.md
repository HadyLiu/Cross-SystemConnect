# 开发环境搭建

> Cross-SystemConnect（CSC）v1.0 · Rust · **不使用 MSVC**  
> Windows 使用 **MSYS2 UCRT64 + x86_64-pc-windows-gnu**；Linux 使用系统 `rustc` / `cargo`。

更完整的产品与架构说明见 [设计方案.md](设计方案.md)。

---

## 1. Windows（推荐：MSYS2 UCRT64）

### 1.1 安装 MSYS2

1. 从 [https://www.msys2.org/](https://www.msys2.org/) 安装 MSYS2。
2. 打开 **UCRT64** 终端（不要用 MSYS / MINGW32）。
3. 更新并安装工具链：

```bash
pacman -Syu
pacman -S --needed mingw-w64-ucrt-x86_64-toolchain mingw-w64-ucrt-x86_64-pkgconf
```

4. 将 UCRT64 的 `bin` 加入系统或用户 **PATH**，例如：

```text
C:\msys64\ucrt64\bin
```

（若安装路径不同，改为你的实际路径。）确认：

```bash
gcc --version
```

### 1.2 安装 Rust（GNU 工具链）

```bash
# 安装 rustup 后：
rustup toolchain install stable-x86_64-pc-windows-gnu
rustup default stable-x86_64-pc-windows-gnu
```

在本仓库目录里执行 `rustup show`，`active toolchain` 应为 `stable-x86_64-pc-windows-gnu`。

`.cargo/config.toml` 只在编译 Windows GNU 目标时指定 `gcc` / `ar`，**不会**把 Linux 改成交叉编译 Windows。

**不要**使用 `x86_64-pc-windows-msvc` / Visual Studio `link.exe`。

### 1.3 WebView2 Runtime

设置界面依赖 Edge WebView2。一般 Windows 10/11 已自带；若缺失请安装：  
[WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)

### 1.4 克隆与构建

```bash
git clone https://github.com/HadyLiu/Cross-SystemConnect.git
cd Cross-SystemConnect

# PATH 需能找到 gcc
cargo build --release -p csc-core -p csc-ui
cargo test
```

产物路径示例：

```text
target/release/Cross-SystemConnect-core.exe
target/release/Cross-SystemConnect.exe
```

`target/` 为生成目录，**不要提交到 Git**（已在 `.gitignore` 中忽略）。

## 2. Linux

### 2.1 依赖（Debian / Ubuntu 示例）

```bash
sudo apt update
sudo apt install build-essential pkg-config \
  libwebkit2gtk-4.1-dev \
  libx11-dev libxi-dev libxtst-dev libxfixes-dev libxrandr-dev \
  libxdo-dev \
  libayatana-appindicator3-dev
```

（具体 WebKitGTK 包名以 wry / 发行版文档为准。）

### 2.2 Rust

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
rustc --version
```

不要在 Linux 上安装或写死 `stable-x86_64-pc-windows-gnu`。仓库不再用 `rust-toolchain.toml` 指定 Windows 工具链；进入目录后 `rustc --version` 应显示本机 Linux 目标。

### 2.3 构建

```bash
cargo build --release -p csc-core -p csc-ui
cargo test
```

v1 键鼠捕获以 **X11** 会话为准；Wayland 见设计方案后续计划。

## 3. 运行与调试

```bash
# 仅内核（无 UI）
cargo run -p csc-core

# 托盘 UI（自动拉起内核；默认不弹窗）
cargo run -p csc-ui
# 启动并立即打开设置
cargo run -p csc-ui -- --open-settings
```

| 项目 | Windows | Linux |
|------|---------|-------|
| 配置 | `%APPDATA%\Cross-SystemConnect\config.json`（兼容迁移旧 `CSC`） | `~/.config/cross-systemconnect/config.json` |
| 日志 | `%APPDATA%\Cross-SystemConnect\Cross-SystemConnect.log` | `~/.local/state/cross-systemconnect/` |
| 本机 IPC | Named Pipe `\\.\pipe\Cross-SystemConnect-core` | `$XDG_RUNTIME_DIR/cross-systemconnect-core.sock` |

常用环境变量：

```bash
# 提高日志级别（若代码侧支持 RUST_LOG / tracing filter）
set RUST_LOG=info
# Linux:
export RUST_LOG=info
```

## 5. 常见问题

**Q: 第一次 `cargo build --release` 很慢？**  
A: 正常。`windows` / `wry` / `webview2-com` 等依赖首次编译耗时长。日常请用：

```bash
cargo build -p csc-core -p csc-ui          # dev，增量快
cargo build --release -p csc-core -p csc-ui # 仅发布时
```

仓库已关闭 release LTO、限制 tokio 特性，以缩短链接与编译时间。

**Q: `error: target tuple in channel name 'stable-x86_64-pc-windows-gnu'`**  
A: 当前目录把工具链写成了 Windows 目标，Linux 上的 rustup 会直接拒绝，`rustc --version` 也会失败。更新到去掉 `rust-toolchain.toml` 的版本后，重新开一个终端再执行 `source "$HOME/.cargo/env"` 和 `rustc --version`。

**Q: `linker 'link.exe' not found`**  
A: 当前在用 MSVC 工具链。执行 `rustup default stable-x86_64-pc-windows-gnu`，并确认在本仓库目录下 `rustc -vV` 的 `host` 为 `x86_64-pc-windows-gnu`。

**Q: `gcc.exe` / linker not found**  
A: 把 MSYS2 `ucrt64\bin` 加入 PATH，新开终端后再 `cargo build`。

**Q: 设置窗空白 / WebView 打不开**  
A: 安装或修复 WebView2 Runtime；确认以 GUI 方式运行 `csc-ui`（非纯无头服务器环境）。

**Q: 能否提交 `target/`？**  
A: 不能。生成物已由 `.gitignore` 排除，只提交源码与文档。
