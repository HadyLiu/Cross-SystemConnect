## 1. 项目概述

Cross-SystemConnect（下称 CSC）是一款跨平台的**键鼠共享**软件。用一套键盘鼠标控制多台电脑（Windows 与 Linux 混用），并支持：

- **键鼠共享**：鼠标移动到屏幕边缘时，自动切换到相邻电脑，键盘输入跟随。
- **剪贴板共享**：在一台电脑上 `Ctrl+C`，在另一台电脑上 `Ctrl+V`。文字直接同步；文件在按 `Ctrl+V` 的那一刻才传到那台电脑的接收目录。
- **文件拖拽**：把文件从一台电脑的窗口拖过屏幕边缘，继续拖着放到另一台电脑的桌面或文件夹中，手感接近本机拖动。
- **被控端之间互传**：两台被控端之间的复制粘贴和拖拽经键鼠主机中转。

所有操作都在后台自动完成，用户**不需要在软件里点击「发送」或「接收」**。

### 1.1 典型使用场景

```
            Wi-Fi（各自上网）
   ┌──────────────┐          ┌──────────────┐
   │  Windows PC  │  网线直连 │   Linux PC   │
   │ 192.168.100.1│◄────────►│192.168.100.2 │
   │ （键鼠在此）  │  CSC 通信 │              │
   └──────────────┘          └──────────────┘
```

- 两台电脑各自通过 Wi-Fi 上网。
- 两台电脑之间用一根网线直连（或 USB 网卡加网线、USB4 直连），专门给 CSC 通信用。
- 直连网卡只配置 IP 和掩码，**不配置网关和 DNS**，保证上网流量不走直连线。

### 1.2 术语

| 术语 | 含义 |
|------|------|
| 服务端（Server） | 物理键鼠所在的电脑，负责捕获输入、判断切换 |
| 客户端（Client） | 被控制的电脑，负责注入输入 |
| 活动屏幕 | 当前正在接收键鼠输入的电脑 |
| 屏幕布局 | 键鼠主机在中间，已连接的电脑放在上下左右或四个角。名字用软件里的计算机名，要和对方一致 |
| 共享剪贴板 | 复制文件时只把条目清单告诉键鼠主机，不传内容、不改其他电脑的剪贴板；在另一台电脑按 `Ctrl+V` 时才传输 |
| 虚拟文件 | 跨屏拖拽时，目标电脑上由 CSC 发起的系统拖拽里的文件。放下后才真正传输内容 |
| 中转 | 被控端之间的传输由键鼠主机按顺序转发，不落盘 |
| 内核（core） | `csc-core` 进程：网络、键鼠、剪贴板、文件，无 UI |
| 界面（ui） | `csc-ui` 进程：托盘与设置 WebView，经本机 IPC 控制内核 |

### 2.2 非功能需求

| 项目 | 目标 |
|------|------|
| 键鼠延迟 | 直连千兆网络下，输入到注入小于 2 ms |
| 文件传输速度 | 千兆直连下不低于 100 MB/s |
| 资源占用 | 空闲时 CPU 小于 1%，内存小于 50 MB（core）；UI 按需 |
| 稳定性 | 连续运行 7 天无崩溃、无内存泄漏 |
| 易用性 | 开机自启内核，托盘常驻，平时无需任何操作 |

### 2.3 不做的事情（v1）

- 不做局域网自动发现之外的公网穿透。
- 不做音频、屏幕画面共享。
- macOS 暂不支持（架构上预留）。

## 3. 总体架构

### 3.1 双进程模型

```
┌─────────────────────┐   本机 IPC（JSON）    ┌──────────────────────────────┐
│  csc-ui             │◄────────────────────►│  csc-core                     │
│  托盘 + WebView     │  Named Pipe / UDS    │  切换 / 剪贴板 / 文件 / 网络   │
│  (tao + wry)        │                      │  平台抽象（win / linux）       │
└─────────────────────┘                      └──────────────┬───────────────┘
                                                            │ TCP/TLS 24900
                                                            ▼
                                                     对端 CSC（peer）
```

- **csc-core**：无界面后台进程。负责键鼠捕获/注入、切换状态机、剪贴板、文件传输、跨机 TCP、配置读写、日志。可独立运行。
- **csc-ui**：托盘与设置窗。不直接碰钩子/网络；全部经 IPC 调用 core。启动时若 IPC 连不上则 spawn `csc-core` 再重试。
- **UI 技术栈**：与 Tauri 同栈的 **tao（窗口）+ wry（WebView2 / WebKitGTK）+ tray-icon**；Clash 风格 HTML 静态资源内嵌；前端通过 `invoke` 风格桥接到 Rust，再转发 IPC。
- **不**再监听本机 HTTP 配置端口，**不**打开系统浏览器。

### 3.2 分层（core 内部）

```
┌────────────────────────────────────────────────────┐
│              IPC 服务（本机 JSON API）                │
├────────────────────────────────────────────────────┤
│                     核心层 Core                      │
│  切换 │ 剪贴板/共享剪贴板 │ 文件传输 │ 中转 │ 拖拽 │ 进度 │
├────────────────────────────────────────────────────┤
│              网络层 Net（Tokio）+ 链路监督            │
│   每个对端一条 TLS 连接：tx 队列（输入/控制）优先，     │
│   bulk 队列（文件、大段文字）其次                     │
├────────────────────────────────────────────────────┤
│           平台抽象层 Platform（trait + 函数）          │
│  输入捕获/注入  原始位移  Ctrl+V 观察  剪贴板           │
│  屏幕与网卡     通知      虚拟文件拖拽源（vdrag）       │
├──────────────────────────┬─────────────────────────┤
│     Windows 实现          │      Linux 实现（X11）    │
│ LL 钩子 / Raw Input      │ XGrab / XI2 RawMotion    │
│ SendInput / OLE 拖拽源   │ XTest / XDND（x11rb）    │
└──────────────────────────┴─────────────────────────┘
```

- **平台抽象层**：Rust `trait` 和 `csc-platform` 的函数隔离系统差异；core 业务不写平台 API（少数行为差异用 `cfg!(windows)` 判断）。
- **网络层**：Tokio 异步 TCP，连接始终是 TLS 1.3（rustls）。文件和键鼠走同一条连接的两个队列，写出时优先键鼠。发现用的 UDP 只带计算机名和端口。
- **跨机协议**：帧格式见 §6。

### 3.3 进程与线程

- **csc-core**
  - Tokio 多线程 runtime：主循环（8 ms）、网络会话、IPC、传输引擎、中转转发、拖拽任务。
  - OS 线程：输入钩子（Windows 消息循环 / X11 连接）、剪贴板、每次拖拽一个拖拽源线程。
- **csc-ui**
  - UI 线程：托盘、设置窗、边缘窗、接收进度窗、选目录对话框。
  - 状态轮询线程：每 80 ms `get_status`，更新边缘窗和进度窗；信任提示轮询线程（800 ms）。
- Core **单实例**以本机 IPC 为准：Windows 用命名管道的首个实例，Linux 在套接字已可连接时不再占用。第二个内核发现端点已被占用后直接退出，避免再抢控制端口 24900。锁文件不是真正的互斥。UI 启动时若内核已在运行，就连到现有内核。

### 3.4 本机 IPC

| 平台 | 端点 |
|------|------|
| Windows | Named Pipe `\\.\pipe\Cross-SystemConnect-core` |
| Linux | Unix Domain Socket `$XDG_RUNTIME_DIR/cross-systemconnect-core.sock` |

帧：`u32 LE length` + UTF-8 JSON body。

请求示例：

```json
{"id":1,"method":"get_status","params":{}}
{"id":2,"method":"get_config","params":{}}
{"id":3,"method":"save_config","params":{ /* Config JSON */ }}
{"id":4,"method":"set_sharing_enabled","params":{"enabled":true}}
{"id":5,"method":"drag_enter","params":{"peer":"linux-pc","paths":["/home/u/a.txt"]}}
{"id":6,"method":"resolve_conflict","params":{"transferId":7,"decisions":[{"index":0,"choice":"keep_both"}]}}
{"id":7,"method":"quit","params":{}}
```

响应：`{"id":1,"ok":true,"result":{...}}` 或 `{"id":1,"ok":false,"error":"..."}`。

方法与语义对齐历史 `getConfig` / `saveConfig` / `getStatus`。第 42–50 条新增 `drag_enter`、`cancel_transfer`、`dismiss_transfer`、`resolve_conflict`、`receive_dir`；`get_status` 的结果新增 `transfers`（接收进度）。完整列表见 [软件架构.md §4.1](软件架构.md)。

## 5. 各功能实现方案

### 5.1 键鼠共享

#### 5.1.1 服务端捕获

在本机时，主循环每 8 ms 读取光标位置判断是否到边，同时读取原始相对位移（光标被屏幕边挡住时，只有原始位移还能反映「继续往外推」）。切到远端后开启抓取，吞掉本机键鼠并转发。

| 平台 | 当前 |
|------|------|
| Windows | 光标位置轮询；原始位移用 Raw Input（`RIDEV_INPUTSINK`）；抓取用 `WH_MOUSE_LL` / `WH_KEYBOARD_LL` 钩子线程 |
| Linux X11 | 光标位置轮询；原始位移用 XInput2 `XI_RawMotion`（运行时加载 `libXi`）；抓取用 `XGrabPointer` / `XGrabKeyboard` |
| Linux Wayland | 后续：`libei` + XDG Desktop Portal。没有 XWayland 时不能注入 |

#### 5.1.2 切换逻辑

1. 键鼠主机的光标到达布局里有邻居的边或角，**并继续往外推过 `switch.edge_push_px`（默认 8 像素的原始位移）**才切换；沿边滑动或往回移动会清零。没有对角邻居时，角是死区，要从边的中段穿过去。
2. 对端 `HELLO` 里的屏幕宽高都大于 1 才切换。尺寸未知时不抢走本机指针。
3. 主机发送 `SWITCH_ENTER`。边上的方向是对端靠近主机的那一侧，光标从那边进入。
4. 本机光标留在刚越过的边内侧，不隐藏，也不拽到屏幕中心。物理鼠标的位移和按键发给对端。
5. **离开由被控端判定**：被控端每次注入移动后读取真实指针位置，压在外侧边上并推够 `edge_push_px` 时发 `EDGE_HIT`；主机收到后回到本机或跳到下一台。对端是旧版本（没有 `CAP_EDGE_REPORT`）时，主机按推算坐标判断。
6. 按住左键拖着文件到边时，进入跨屏拖拽（5.4），不走普通切换。

#### 5.1.3 客户端注入

| 平台 | 方案 |
|------|------|
| Windows | `SetCursorPos` 移动指针；按键与滚轮用 `SendInput` |
| Linux X11 | 运行时打开 `libX11.so.6`、`libXtst.so.6`，用 XTest 移动指针和按键。缺库时进程仍能启动 |
| Linux 通用 | 备选 `uinput`，尚未作为主路径 |

### 5.2 剪贴板共享

- 剪贴板线程每 400 ms 读取系统剪贴板（arboard；Windows 先比较剪贴板序号），发现变化后交给主循环；序号抑制回环。
- **文字**：放进 `CLIP_OFFER` 发给所有对端，主机收到被控端的文字也转给其他被控端。上限 `clipboard.max_inline_mb`，默认即最大值 15 MB，超出时发系统通知不同步。超过 64 KB 的文字走 `bulk` 队列，不卡鼠标。
- **文件**（`clipboard.files`）：复制时不传内容，也**不改任何电脑的剪贴板**。被控端只把条目清单告诉主机，主机记下「最后一次复制的是哪台电脑上的哪些文件」。

### 5.3 文件复制粘贴

1. 键鼠主机知道 `Ctrl+V` 按在哪台电脑上：在本机时由平台层观察按键（Windows 钩子、Linux 对根窗口被动抓取 Ctrl+V）；在远端时本来就在转发按键。
2. 如果最后复制的是**另一台**电脑上的文件，主机吞掉这次 `Ctrl+V`，改为把文件传到按键那台电脑的接收目录（用途 `Paste`）。复制和粘贴在同一台电脑时，`Ctrl+V` 照常交给系统。
3. 文件在主机上就直接发；在被控端上就发 `PASTE_REQUEST {to}` 让它发，目标是另一台被控端时经主机中转（5.5）。
4. 同一批文件、同一目标 3 s 内重复按只算一次。
5. 传输流程：`FILE_OFFER` →（有重名时在接收端进度窗里选择）→ `FILE_REQUEST {skip}` → `FILE_BEGIN` / `FILE_DATA`（64 KB 一块）/ `FILE_END`（xxHash64 校验）→ `FILE_DONE`。接收端每写入 1 MiB 回 `FILE_ACK`，发送端未确认超过 8 MiB 时暂停。
6. **接收目录**：`file_transfer.receive_dir`，为空表示桌面；设置页可以「浏览…」选择，也可以「打开」。
7. **进度窗**：只在接收端弹出，显示每批的进度、速度、剩余时间，可以取消、打开保存位置；完成的条目保留 30 s。发送端不弹窗。
8. **重名**：顶层名称已存在时，进度窗里逐项选择跳过 / 保留两者 / 替换（默认保留两者，多项时有「全部」按钮），点「继续」后开始传输。保留两者命名为「原名 (1).扩展名」「(2)」…；替换时先写临时文件，校验通过后才覆盖，失败时原文件完好。

### 5.4 跨屏拖拽

1. 源端按住左键拖着文件到有邻居的边时，边缘出现一条细窗（对端支持虚拟拖拽时 4–12 px）。文件拖进细窗后，源端预检并登记这批文件，注入 Esc 取消本机拖拽，然后切换到目标电脑（被控端是源端时发 `EDGE_HIT{dragging}`）。
2. 源端发 `DRAG_BEGIN {transfer_id, entries, total_bytes, origin}`；来自被控端时，主机按刚才的路由交给本机或转给另一台被控端。
3. 目标端用这些条目发起一次**系统拖拽**，指针上挂着虚拟文件，用户继续拖到想放的地方：
   - **Windows**：OLE 拖拽源（`FileGroupDescriptorW` + `FileContents`，支持异步提取）。放下后资源管理器从暂存文件边收边读，放到哪里就存到哪里；重名由资源管理器询问。
   - **Linux，文件管理器支持 XDS**：拿到放下的目录，直接写入。
   - **Linux，不支持 XDS**：提供和被拖文件**同名**的虚拟文件（小占位文件，文件夹里带标记文件）。放下后，文件管理器会把它们复制到目标位置；CSC 按内容在家目录（6 层内）、`/media`、`/mnt` 等处找到这些副本，再把真实内容写到同一位置。文件管理器把副本改成别的名字时，统一改为「原名 (1)」的形式。20 s 内找不到时存到接收目录并通知。
4. 松手后不询问，直接传输，目标端显示进度窗。放到不接收文件的地方或按 Esc（Windows）时，这次拖拽取消，源端预登记的批次一并清除。
5. 对端是旧版本（没有 `CAP_VIRTUAL_DRAG`）时，退回旧方式：在边缘投放窗上松手，传到对方的接收目录。

### 5.5 被控端之间经主机中转

- 被控端之间不直接连接。粘贴：主机发出 `PASTE_REQUEST {to}` 时登记一次中转许可（120 s 内有效），被控端发来带 `relay_to` 的 `FILE_OFFER` 时主机取用许可，没有许可就拒绝。拖拽：主机按处理 `EDGE_HIT{dragging}` 时记下的路由转发 `DRAG_BEGIN`。
- 主机为每条中转新建路由，改写 `transfer_id` 后按顺序转发，不落盘。
- 流量控制逐跳进行：主机每把 1 MiB 交给目标链路，就以自己的身份向源端回一次 `FILE_ACK`；目标端的确认由主机吸收。源端窗口只有 8 MiB，所以主机上的积压不会超过约 8 MiB，也不会阻塞键鼠。
- 任一方断开时，路由和未完成的传输一并清除，两端都收到失败通知。

## 6. 网络与协议

### 6.1 连接

| 通道 | 端口（默认） | 用途 |
|------|------------|------|
| 控制通道 | TCP 24900 | 键鼠、切换、剪贴板清单、心跳（`TCP_NODELAY`） |
| 数据端口 | TCP 24901 | 配置里预留，当前未使用 |

- 文件和超过 64 KB 的文字也走控制通道的同一条 TLS 连接，但放在单独的 `bulk` 队列里；写出时优先键鼠和控制帧，大文件传输不会拖慢鼠标。
- 发现用控制端口上的 UDP，魔数 `CSCD`。键鼠主机只扫描当前选中网卡的 /24，然后主动连被控端的 TCP。两边要选同一网段。
- 被控端弹出信任提示，只有「信任」和「取消」。信任会记下键鼠主机的证书指纹；取消则拒绝，短时间内不再重复询问。证书变了会再问一次。键鼠主机侧不弹这个提示，但会记住被控端的第一张证书，之后换证书就拒绝连接。被控端在提示期间每 2 s 发心跳，主机 10 s 收不到任何字节才放弃。
- 心跳可配；断线时解除独占，键鼠回本机。
- **自动重连**：会话结束时立即发一轮发现；主机按 2 s 起、最长 10 s 的退避直接重拨被控端上次的地址。链路监督在选中网卡的地址消失后恢复、地址变化、或被控端长时间没有会话时自动重建网络，效果等同界面上的「刷新」（刷新按钮保留作兜底）。

### 6.2 消息格式

小端帧头 12 字节：

```
 magic('C','S') | ver(u8) | type(u8) | flags(u32) | length(u32) | payload
```

### 6.3 消息类型

| type | 名称 | 说明 |
|------|------|------|
| 0x01 | HELLO | 版本、主机名、屏幕、能力位 |
| 0x02 | HEARTBEAT | 心跳 |
| 0x10 | SWITCH_ENTER | 进入客户端 |
| 0x11 | SWITCH_LEAVE | 离开客户端 |
| 0x12 | EDGE_HIT | 被控端报告真实指针推到了外侧边：`{edge, position_pct, dragging, corner}` |
| 0x20–0x23 | MOUSE_* / KEY | 输入 |
| 0x30–0x32 | CLIP_OFFER / CLIP_REQUEST / CLIP_DATA | 剪贴板；`CLIP_OFFER` 可以只带文件条目清单 |
| 0x33 | PASTE_REQUEST | 主机请求被控端把最后复制的文件发给 `to` |
| 0x40 | DRAG_BEGIN | 跨屏拖拽开始：`{transfer_id, entries, total_bytes, to, origin}` |
| 0x41 | DRAG_CANCEL | 拖拽取消：`{transfer_id, reason}` |
| 0x50–0x54 | FILE_REQUEST / FILE_DATA / FILE_END / FILE_CANCEL / FILE_ERROR | 文件传输；`FILE_REQUEST` 带 `skip`（重名时跳过的条目） |
| 0x55–0x57 | FILE_OFFER / FILE_BEGIN / FILE_DONE | 文件传输；`FILE_OFFER` 带 `purpose`、`origin`、`relay_to` |
| 0x58 | FILE_ACK | 接收端确认已写入的字节数（每 1 MiB） |

能力位（`HELLO.capabilities`）：`CAP_VIRTUAL_DRAG`=1（本机能做虚拟文件拖拽源）、`CAP_EDGE_REPORT`=2、`CAP_FILE_ACK`=4。缺少某一位时，按旧方式处理，协议版本仍为 1。

### 6.4 安全

- 控制通道是 TLS 1.3。每台电脑在配置目录生成 `identity.crt` 和 `identity.key`（自签名）。`peer_fingerprints` 按计算机名保存对方证书的 SHA-256。
- 发现 UDP 不加密，里面没有键鼠数据。旧的明文程序无法再连上。
- 文件路径规范化，拒绝 `..` 与绝对路径。

## 7. 配置

- Windows：`%APPDATA%\Cross-SystemConnect\config.json`（兼容迁移旧 `%APPDATA%\CSC\`）
- Linux：`~/.config/cross-systemconnect/config.json`
- 默认 `name` = **本机计算机名**；默认 `role` = **client**（配置中已为 server 则保持）
- 日志：`%APPDATA%\Cross-SystemConnect\Cross-SystemConnect.log` 或 `~/.local/state/cross-systemconnect/`
- 本机证书：配置目录下的 `identity.crt`、`identity.key`。私钥不要拷到别的电脑。

字段语义与历史 JSON 兼容（`role` / `layout` / `switch` / `clipboard` / `gui` / `network` 等）。第 42–50 条相关的字段：

| 字段 | 说明 |
|------|------|
| `config_version` | 当前 2。旧文件没有这个字段，按 1 处理，读取时迁移一次（文字上限改为 15） |
| `clipboard.max_inline_mb` | 文字剪贴板上限，默认 15，范围 1–15 |
| `clipboard.files` | 复制文件后可以在另一台电脑按 `Ctrl+V` 传输，默认开 |
| `file_transfer.receive_dir` | 接收目录；空表示桌面，取不到桌面时依次退到下载目录、配置目录下的 `received` |
| `switch.edge_push_px` | 到边后还要继续推多少原始位移才切换，默认 8，范围 0–200 |

`clipboard.max_total_mb` 已删除。

屏幕位置只在键鼠主机的首页显示，不画网格。主机固定在中间，只显示已经连上的电脑。方块可拖到上下左右和四个角，间距 5 像素；拖动时跟着鼠标，松开后吸到最近的空位。画布大小固定。布局里的名字是软件中的计算机名，修改它不会改 Windows 或 Linux 的系统计算机名。旧的小坐标和旧间距会在界面里换算到当前间距。

## 9. 构建

开发机环境搭建、FAQ 与逐步说明见 **[开发环境.md](开发环境.md)**（Windows MSYS2 UCRT64 + GNU，不使用 MSVC）。

### 9.1 依赖

| 库 | 用途 |
|----|------|
| tokio | 异步 runtime / TCP / 时间 |
| serde / serde_json | 配置与 IPC |
| tracing / tracing-subscriber | 日志 |
| rustls / tokio-rustls | TLS |
| windows / windows-core | Windows 钩子、Raw Input、剪贴板、屏幕信息、OLE 拖拽源（`implement`）；UI 里的 `IFileOpenDialog` 选目录 |
| libX11 / libXtst | Linux 运行时打开 `libX11.so.6`、`libXtst.so.6`（包名 `libx11-6`、`libxtst6`） |
| libXi | Linux 运行时打开 `libXi.so.6`（包名 `libxi6`），读原始鼠标位移；缺库时退回「到边就切换」的旧行为 |

### 9.2 编译命令

```bash
cargo build --release -p csc-core -p csc-ui
cargo test
```

Windows 需安装 **WebView2 Runtime**，且 PATH 含 MSYS2 `ucrt64\bin`（`gcc`）。Linux 编译需 WebKitGTK 等；运行被控端还需 `libx11-6`、`libxtst6`，以及 X11 或 XWayland。详见开发环境文档。

### 9.3 运行

```bash
# 仅内核（可开机自启）
./target/release/Cross-SystemConnect-core.exe
# 或: cargo run -p csc-core

# 界面（自动拉起 core）
cargo run -p csc-ui
cargo run -p csc-ui -- --open-settings
```

### 9.4 驻留行为

| 状态 | csc-core | 托盘 | 设置 WebView |
|------|----------|------|----------------|
| 正常 | 运行 | 显示 | 隐藏 |
| 打开设置 | 运行 | 显示 | 显示 |
| 关闭设置 | 运行 | 显示 | 隐藏 |
| 退出 | 停止 | 移除 | 销毁 |

只有托盘「退出」才通知 core `quit` 并结束 UI。

Windows 托盘双击或右键「设置」打开窗口，右键另一项是「退出」。Linux 托盘用 StatusNotifierItem：左键打开设置，右键同样只有「设置」和「退出」；双击不会打开窗口。

## 13. 已知限制与风险

| 项目 | 说明 | 应对 |
|------|------|------|
| Wayland | 没有 XWayland 时不能注入指针 | v1 要求 X11 或 XWayland；后续 libei |
| Linux 运行库 | 缺 `libxtst6` / `libx11-6` 时编译仍成功，指针不动 | 运行机安装这两个包 |
| Linux 缺 `libxi6` | 读不到原始位移，主机退回「到边就切换」，第 46 条不生效 | 运行机安装 `libxi6` |
| 拖到 Windows 资源管理器 | 重名对话框和「保留两者」的命名由资源管理器决定（「原名 (2)」） | 无法控制 |
| 不支持 XDS 的 Linux 文件管理器 | 放到搜索范围外或 20 s 内没找到副本时，改存到接收目录；20 s 后才出现的占位副本不会自动删除 | 通知保存位置 |
| Linux 目标端拖拽中按 Esc | 拖拽源只抓指针不抓键盘，Esc 不能取消 | 移回源端或放到不接收文件的地方 |
| 旧版本对端 | 缺少能力位时退回旧行为；信任提示期间的心跳、中转要求相关电脑都升级 | 同时升级 |
| 安全桌面 | UAC/登录界面 | v1 不做 |
| 管理员窗口 | 普通权限注入无效 | 可选提权运行 |
| WebView2 | 需 Runtime | 安装说明 / Evergreen |
