# Cross-SystemConnect 说明文档

> 版本：v1.0（Rust 重构：双进程 UI / 内核分离）
> 日期：2026-09-30
> 语言：Rust 2021
> 平台：Windows 10/11、Linux（X11 优先，Wayland 后续支持）
> 工具链：`rustc` / `cargo`（Windows：**MSYS2 UCRT64 + x86_64-pc-windows-gnu**，不使用 MSVC；Linux：系统 rustc）
> 界面：`Cross-SystemConnect` 托盘 + Clash 风格 WebView 设置窗；`Cross-SystemConnect-core` 无界面内核常驻
> 默认角色：client；已保存为 server（键鼠主机）则沿用

---

## 1. 项目概述

Cross-SystemConnect（下称 CSC）是一款跨平台的**键鼠共享**软件。用一套键盘鼠标控制多台电脑（Windows 与 Linux 混用），并支持：

- **键鼠共享**：鼠标移动到屏幕边缘时，自动切换到相邻电脑，键盘输入跟随。
- **剪贴板共享**：在一台电脑上 `Ctrl+C`，在另一台电脑上 `Ctrl+V`，支持文本、图片和文件。
- **文件拖拽**：把文件从一台电脑的窗口拖过屏幕边缘，放到另一台电脑的桌面或文件夹中。

所有操作都在后台自动完成，用户**不需要在软件里点击「发送」或「接收」**。

### 1.1 典型使用场景

```
            Wi-Fi（各自上网）
   ┌──────────────┐          ┌──────────────┐
   │  Windows PC  │  网线直连 │   Linux PC   │
   │ 192.168.100.1│◄────────►│192.168.100.2 │
   │ （键鼠在此）  │  CSC 通信 │              │
   └──────────────┘          └──────────────┘
```

- 两台电脑各自通过 Wi-Fi 上网。
- 两台电脑之间用一根网线直连（或 USB 网卡加网线、USB4 直连），专门给 CSC 通信用。
- 直连网卡只配置 IP 和掩码，**不配置网关和 DNS**，保证上网流量不走直连线。

### 1.2 术语

| 术语 | 含义 |
|------|------|
| 服务端（Server） | 物理键鼠所在的电脑，负责捕获输入、判断切换 |
| 客户端（Client） | 被控制的电脑，负责注入输入 |
| 活动屏幕 | 当前正在接收键鼠输入的电脑 |
| 屏幕布局 | 键鼠主机在中间，已连接的电脑放在上下左右或四个角。名字用软件里的计算机名，要和对方一致 |
| 延迟渲染 | 复制文件时只传元数据，粘贴时才真正传输文件内容 |
| 内核（core） | `csc-core` 进程：网络、键鼠、剪贴板、文件，无 UI |
| 界面（ui） | `csc-ui` 进程：托盘与设置 WebView，经本机 IPC 控制内核 |

### 2.2 非功能需求

| 项目 | 目标 |
|------|------|
| 键鼠延迟 | 直连千兆网络下，输入到注入小于 2 ms |
| 文件传输速度 | 千兆直连下不低于 100 MB/s |
| 资源占用 | 空闲时 CPU 小于 1%，内存小于 50 MB（core）；UI 按需 |
| 稳定性 | 连续运行 7 天无崩溃、无内存泄漏 |
| 易用性 | 开机自启内核，托盘常驻，平时无需任何操作 |

- 不做局域网自动发现之外的公网穿透。
- 不做音频、屏幕画面共享。
- macOS 暂不支持（架构上预留）。

## 3. 总体架构

### 3.1 双进程模型

```
┌─────────────────────┐   本机 IPC（JSON）    ┌──────────────────────────────┐
│  csc-ui             │◄────────────────────►│  csc-core                     │
│  托盘 + WebView     │  Named Pipe / UDS    │  切换 / 剪贴板 / 文件 / 网络   │
│  (tao + wry)        │                      │  平台抽象（win / linux）       │
└─────────────────────┘                      └──────────────┬───────────────┘
                                                            │ TCP 24900/24901
                                                            ▼
                                                     对端 CSC（peer）
```

- **csc-core**：无界面后台进程。负责键鼠捕获/注入、切换状态机、剪贴板、文件传输、跨机 TCP、配置读写、日志。可独立运行。
- **csc-ui**：托盘与设置窗。不直接碰钩子/网络；全部经 IPC 调用 core。启动时若 IPC 连不上则 spawn `csc-core` 再重试。
- **UI 技术栈**：与 Tauri 同栈的 **tao（窗口）+ wry（WebView2 / WebKitGTK）+ tray-icon**；Clash 风格 HTML 静态资源内嵌；前端通过 `invoke` 风格桥接到 Rust，再转发 IPC。
- **不**再监听本机 HTTP 配置端口，**不**打开系统浏览器。

### 3.2 分层（core 内部）

```
┌────────────────────────────────────────────────────┐
│              IPC 服务（本机 JSON API）                │
├────────────────────────────────────────────────────┤
│                     核心层 Core                      │
│  SwitchController │ ClipboardSync │ FileTransfer │ Drag │
├────────────────────────────────────────────────────┤
│                    网络层 Net（Tokio）                │
│      控制通道（TCP）      │     数据通道（TCP）        │
├────────────────────────────────────────────────────┤
│                 平台抽象层 Platform（trait）           │
│  InputCapture  InputInjector  Clipboard               │
│  DragDrop      ScreenInfo     AutoStart               │
├──────────────────────────┬─────────────────────────┤
│     Windows 实现          │      Linux 实现          │
│ GetCursorPos / SendInput │ X11：运行时打开 XTest     │
└──────────────────────────┴─────────────────────────┘
```

- **平台抽象层**：Rust `trait` 隔离系统差异；core 业务不写 `cfg!(windows)` 分支（实现放在 `csc-platform`）。
- **网络层**：Tokio 异步 TCP，控制通道始终是 TLS 1.3（rustls）。发现用的 UDP 只带计算机名和端口。
- **跨机协议**：帧格式见 §6。

### 3.3 进程与线程

- **csc-core**
  - Tokio 多线程 runtime：网络、IPC、文件 IO。
  - 平台输入钩子可能需要独立 OS 线程 + 消息循环（Windows）；事件经 channel 送入 Tokio。
- **csc-ui**
  - UI 线程：窗口 / WebView / 托盘。
  - 后台任务：IPC 客户端（短轮询 `get_status` 或异步请求）。
- Core **单实例**以本机 IPC 为准：Windows 用命名管道的首个实例，Linux 在套接字已可连接时不再占用。第二个内核发现端点已被占用后直接退出，避免再抢控制端口 24900。锁文件不是真正的互斥。UI 启动时若内核已在运行，就连到现有内核。

### 3.4 本机 IPC

| 平台 | 端点 |
|------|------|
| Windows | Named Pipe `\\.\pipe\Cross-SystemConnect-core` |
| Linux | Unix Domain Socket `$XDG_RUNTIME_DIR/cross-systemconnect-core.sock` |

帧：`u32 LE length` + UTF-8 JSON body。

请求示例：

```json
{"id":1,"method":"get_status","params":{}}
{"id":2,"method":"get_config","params":{}}
{"id":3,"method":"save_config","params":{ /* Config JSON */ }}
{"id":4,"method":"set_sharing_enabled","params":{"enabled":true}}
{"id":5,"method":"quit","params":{}}
```

响应：`{"id":1,"ok":true,"result":{...}}` 或 `{"id":1,"ok":false,"error":"..."}`。

方法与语义对齐历史 `getConfig` / `saveConfig` / `getStatus`。

## 4. 平台抽象接口（Rust）

```rust
pub struct MouseEvent { pub dx: i32, pub dy: i32, pub x: i32, pub y: i32,
                        pub buttons: u32, pub wheel_v: i32, pub wheel_h: i32 }
pub struct KeyEvent { pub hid_usage: u32, pub down: bool, pub modifiers: u32 }

pub trait InputCapture: Send {
    fn start(&mut self, on_mouse: Box<dyn FnMut(MouseEvent) -> bool + Send>,
                       on_key: Box<dyn FnMut(KeyEvent) -> bool + Send>) -> anyhow::Result<()>;
    fn stop(&mut self);
    fn set_grab(&mut self, grab: bool);
    fn warp_cursor(&mut self, x: i32, y: i32);
}

pub trait InputInjector: Send {
    fn mouse_move_abs(&mut self, x: i32, y: i32);
    fn mouse_move_rel(&mut self, dx: i32, dy: i32);
    fn mouse_button(&mut self, button: u32, down: bool);
    fn mouse_wheel(&mut self, v: i32, h: i32);
    fn key(&mut self, hid_usage: u32, down: bool);
}

pub trait Clipboard: Send { /* watch / get_text / set_text / files lazy … */ }
pub trait DragDrop: Send { /* current_drag_files / begin_drag / cancel_drag */ }
pub trait ScreenInfo: Send { fn virtual_size(&self) -> ScreenSize; }
pub trait AutoStart: Send { fn is_enabled(&self) -> bool; fn set_enabled(&mut self, on: bool) -> anyhow::Result<()>; }
```

键码统一使用 **USB HID Usage** 作为线上格式。

## 5. 各功能实现方案

### 5.1 键鼠共享

#### 5.1.1 服务端捕获

当前键鼠主机每 8ms 读取本机光标位置来判断穿屏，不依赖低级键盘鼠标钩子。钩子和 Linux `XInput2` 抓取仍是后续路径。

| 平台 | 当前 |
|------|------|
| Windows | `GetCursorPos` 轮询；穿屏后把光标停在刚越过的边内侧，相对位移发给对端 |
| Linux | 注入见 5.1.3；本机捕获尚未作为主路径 |
| Linux Wayland | 后续：`libei` + XDG Desktop Portal。没有 XWayland 时不能注入 |

#### 5.1.2 切换逻辑

1. 键鼠主机的光标到达布局里有邻居的边或角。没有对角邻居时，角是死区，要从边的中段穿过去。
2. 对端 `HELLO` 里的屏幕宽高都大于 1 才切换。尺寸未知时不抢走本机指针。
3. 主机发送 `SWITCH_ENTER`。边上的方向是对端靠近主机的那一侧，光标从那边进入。
4. 本机光标留在刚越过的边内侧，不隐藏，也不拽到屏幕中心。物理鼠标的位移发给对端；往回移出对端靠近的边就回到本机。
5. 键盘跟随仍依赖后续的捕获钩子。接收端可以注入已经收到的按键；Linux 注入端的按键目前是空操作。

#### 5.1.3 客户端注入

| 平台 | 方案 |
|------|------|
| Windows | `SetCursorPos` 移动指针；按键与滚轮用 `SendInput` |
| Linux X11 | 运行时打开 `libX11.so.6`、`libXtst.so.6`，用 XTest 移动指针和按键。缺库时进程仍能启动 |
| Linux 通用 | 备选 `uinput`，尚未作为主路径 |

### 5.2 剪贴板共享

- Windows：`AddClipboardFormatListener`
- Linux X11：XFixes selection
- 按需同步 `CLIP_OFFER` / `CLIP_REQUEST` / `CLIP_DATA`；序号抑制回环

### 5.3 文件复制粘贴 / 5.4 拖拽

- 虚拟文件（Windows `IDataObject`）与 Linux 缓存落地策略同历史设计。
- 边缘透明窗检测拖拽；`DRAG_BEGIN` / `DRAG_CANCEL`；数据通道分块 + xxHash64。

## 6. 网络与协议

### 6.1 连接

| 通道 | 端口（默认） | 用途 |
|------|------------|------|
| 控制通道 | TCP 24900 | 键鼠、切换、剪贴板清单、心跳（`TCP_NODELAY`） |
| 数据通道 | TCP 24901 | 文件与大剪贴板 |

- 发现用控制端口上的 UDP，魔数 `CSCD`。键鼠主机只扫描当前选中网卡的 /24，然后主动连被控端的 TCP。两边要选同一网段。
- 被控端弹出信任提示，只有「信任」和「取消」。信任会记下键鼠主机的证书指纹；取消则拒绝，短时间内不再重复询问。证书变了会再问一次。键鼠主机侧不弹这个提示，但会记住被控端的第一张证书，之后换证书就拒绝连接。
- 心跳可配；断线时解除独占，键鼠回本机。
- 数据端口 24901 已在配置里预留，文件通道尚未作为主路径。

### 6.2 消息格式

小端帧头 12 字节：

```
 magic('C','S') | ver(u8) | type(u8) | flags(u32) | length(u32) | payload
```

### 6.3 消息类型

| type | 名称 | 说明 |
|------|------|------|
| 0x01 | HELLO | 版本、主机名、屏幕、能力 |
| 0x02 | HEARTBEAT | 心跳 |
| 0x10 | SWITCH_ENTER | 进入客户端 |
| 0x11 | SWITCH_LEAVE | 离开客户端 |
| 0x20–0x23 | MOUSE_* / KEY | 输入 |
| 0x30–0x32 | CLIP_* | 剪贴板 |
| 0x40–0x41 | DRAG_* | 拖拽 |
| 0x50–0x54 | FILE_* | 文件传输 |

### 6.4 安全

- 控制通道是 TLS 1.3。每台电脑在配置目录生成 `identity.crt` 和 `identity.key`（自签名）。`peer_fingerprints` 按计算机名保存对方证书的 SHA-256。
- 发现 UDP 不加密，里面没有键鼠数据。旧的明文程序无法再连上。
- 文件路径规范化，拒绝 `..` 与绝对路径。

## 7. 配置

- Windows：`%APPDATA%\Cross-SystemConnect\config.json`（兼容迁移旧 `%APPDATA%\CSC\`）
- Linux：`~/.config/cross-systemconnect/config.json`
- 默认 `name` = **本机计算机名**；默认 `role` = **client**（配置中已为 server 则保持）
- 日志：`%APPDATA%\Cross-SystemConnect\Cross-SystemConnect.log` 或 `~/.local/state/cross-systemconnect/`
- 本机证书：配置目录下的 `identity.crt`、`identity.key`。私钥不要拷到别的电脑。

字段语义与历史 JSON 兼容（`role` / `layout` / `switch` / `clipboard` / `gui` / `network` 等）。

屏幕位置只在键鼠主机的首页显示，不画网格。主机固定在中间，只显示已经连上的电脑。方块可拖到上下左右和四个角，间距 5 像素；拖动时跟着鼠标，松开后吸到最近的空位。画布大小固定。布局里的名字是软件中的计算机名，修改它不会改 Windows 或 Linux 的系统计算机名。旧的小坐标和旧间距会在界面里换算到当前间距。

## 9. 构建

开发机环境搭建、FAQ 与逐步说明见 **[开发环境.md](开发环境.md)**（Windows MSYS2 UCRT64 + GNU，不使用 MSVC）。

### 9.1 依赖

| 库 | 用途 |
|----|------|
| tokio | 异步 runtime / TCP / 时间 |
| serde / serde_json | 配置与 IPC |
| tracing / tracing-subscriber | 日志 |
| rustls / tokio-rustls | TLS |
| windows crate | Windows 钩子、剪贴板、屏幕信息等 |
| libX11 / libXtst | Linux 运行时打开 `libX11.so.6`、`libXtst.so.6`（包名 `libx11-6`、`libxtst6`） |
| tao + wry + tray-icon | UI WebView 与托盘 |
| xxhash-rust | 文件校验 |

### 9.2 编译命令

```bash
cargo build --release -p csc-core -p csc-ui
cargo test
```

Windows 需安装 **WebView2 Runtime**，且 PATH 含 MSYS2 `ucrt64\bin`（`gcc`）。Linux 编译需 WebKitGTK 等；运行被控端还需 `libx11-6`、`libxtst6`，以及 X11 或 XWayland。详见开发环境文档。

### 9.3 运行

```bash
# 仅内核（可开机自启）
./target/release/Cross-SystemConnect-core.exe
# 或: cargo run -p csc-core

# 界面（自动拉起 core）
cargo run -p csc-ui
cargo run -p csc-ui -- --open-settings
```

### 9.4 驻留行为

| 状态 | csc-core | 托盘 | 设置 WebView |
|------|----------|------|----------------|
| 正常 | 运行 | 显示 | 隐藏 |
| 打开设置 | 运行 | 显示 | 显示 |
| 关闭设置 | 运行 | 显示 | 隐藏 |
| 退出 | 停止 | 移除 | 销毁 |

只有托盘「退出」才通知 core `quit` 并结束 UI。

Windows 托盘双击或右键「设置」打开窗口，右键另一项是「退出」。Linux 托盘用 StatusNotifierItem：左键打开设置，右键同样只有「设置」和「退出」；双击不会打开窗口。

## 13. 已知限制与风险

| 项目 | 说明 | 应对 |
|------|------|------|
| Wayland | 没有 XWayland 时不能注入指针 | v1 要求 X11 或 XWayland；后续 libei |
| Linux 运行库 | 缺 `libxtst6` / `libx11-6` 时编译仍成功，指针不动 | 运行机安装这两个包 |
| 键盘穿屏 | 主机侧尚未用钩子捕获键盘 | 接收端可注入已收到的按键；Linux 按键注入仍是空操作 |
| 安全桌面 | UAC/登录界面 | v1 不做 |
| 管理员窗口 | 普通权限注入无效 | 可选提权运行 |
| WebView2 | 需 Runtime | 安装说明 / Evergreen |
